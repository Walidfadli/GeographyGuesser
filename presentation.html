Vue d'ensemble du projet

Qu'est-ce que GeoGuessr Assistant et pourquoi l'a-t-on construit ?

🎯 Objectif

GeoGuessr est un jeu en ligne où le joueur doit deviner sa position sur Terre à partir d'une image Google Street View. Notre outil capture l'écran, puis lance trois classifieurs en parallèle pour proposer la meilleure réponse en quelques secondes.

L'outil n'envoie rien au serveur de jeu : tout est local (sauf Google Vision API pour l'OCR). Il s'utilise sur un second moniteur pendant la partie.

⌨️ Raccourcis clavier

AAnalyser les images & ouvrir Google Maps

⚙️ Les 3 classifieurs

1

Classifieur de Continent (CNN)

Un réseau de neurones convolutif prédit le continent (6 classes : Afrique, Asie, Europe, Amérique du Nord, Océanie, Amérique du Sud) avec un score de confiance.

2

Classifieur de Drapeau (CNN)

Un second CNN identifie les drapeaux visibles dans la capture parmi 80 pays présents dans GeoGuessr, puis affiche le top-6 des pays candidats.

3

Pipeline OCR + Géocodage

Google Vision API extrait le texte visible (panneaux, enseignes…), Nominatim le géocode, et spaCy filtre les résultats par langue pour trouver l'adresse exacte.

Scraping Google Images

80 pays GeoGuessr

Le fichier countries_in_geoguesser.json liste les 80 pays disponibles dans le jeu (codes ISO-2). Ces codes servent de noms de dossiers.

Préparation & Équilibrage des classes

Pourquoi équilibrer ? Comment s'assurer que le modèle apprend équitablement ?

⚠️ Problème de déséquilibre

Certains continents (Europe, Asie) ont beaucoup plus d'images disponibles que d'autres (Océanie, Afrique). Un modèle entraîné sur des données déséquilibrées apprend à favoriser les classes majoritaires.

Deux stratégies combinées :
1️⃣ balance_classes_continents.py / balance_classes_flags.py suppriment les fichiers excédentaires pour ramener toutes les classes au minimum observé.

2️⃣ Les scripts d'entraînement calculent des poids de classe (class_weight) proportionnels à l'inverse de la fréquence, passés à model.fit().

Concepts fondamentaux des CNN

Comprendre les Réseaux de Neurones Convolutifs (Convolutional Neural Networks)

Couche Conv2D
Applique des filtres (kernels) qui glissent sur l'image. Chaque filtre détecte un motif local : bords, couleurs, textures. Paramètres : nb de filtres, taille du kernel, stride.
Activation ReLU
Rectified Linear Unit : f(x) = max(0, x). Introduit la non-linéarité sans saturer le gradient. Standard moderne dans les CNN.
BatchNormalization
Normalise les activations au sein d'un mini-batch. Accélère l'entraînement, réduit la sensibilité au taux d'apprentissage initial.
MaxPooling2D
Sous-échantillonne la carte de features (feature map) en prenant le max dans une fenêtre 2×2. Réduit la dimension spatiale et apporte de l'invariance à la translation.
Dropout
Désactive aléatoirement p% des neurones à chaque passe d'entraînement. Technique de régularisation qui prévient le sur-apprentissage (overfitting).
Dense + Softmax
Couche entièrement connectée. Softmax convertit les logits en probabilités (somme = 1) pour la classification multi-classes.

🔍 Comment un CNN "voit"

Couches basses → détectent bords et couleurs simples
Couches intermédiaires → combinent pour former des formes (routes, végétation, bâtiments)
Couches hautes → abstraction sémantique : "végétation tropicale" = Asie du Sud-Est

Formule de convolution

(I * K)[i,j] = Σ Σ I[i+m, j+n] · K[m,n]

I  = image d'entrée
K  = filtre (kernel) à apprendre
*  = opération de corrélation croisée

Les poids du kernel K sont appris par rétropropagation (backpropagation) via l'optimiseur Adam, minimisant la cross-entropie catégorielle.

Pourquoi un grand kernel 9×9 en premier ?
Un kernel large capture des patterns à plus grande échelle en une seule couche (ex : horizon, ciel). Avec stride=3, la dimension est rapidement réduite avant les couches plus fines (3×3).

Fichier .h5 vs architecture réelle
Les modèles sont nommés _250_250.h5 mais entraînés et utilisés en 150×150. Le nom est une erreur historique — l'architecture dans le code fait foi.

Entraînement & évaluation des modèles

Stratégie d'entraînement, validation et prévention du sur-apprentissage

📉 Stratégie d'entraînement

model.compile(
  optimizer=Adam(lr=0.001),
  loss='categorical_crossentropy',
  metrics=['accuracy']
)

checkpoint = ModelCheckpoint(
  filepath='model.h5',
  monitor='val_loss',     # surveille val
  save_best_only=True
)

model.fit(
  X_train, y_train,
  epochs=2000,           # arrêt manuel
  batch_size=256,
  validation_split=0.3, # 30% val
  class_weight=weights,  # équilibre
  callbacks=[checkpoint]
)

🛡️ Anti-overfitting : triple protection

1

Dropout agressif

Dropout(0.7) après le pooling, Dropout(0.6) et Dropout(0.4) dans les couches denses. Force le réseau à ne pas mémoriser les exemples.

2

BatchNormalization

Stabilise et régularise implicitement l'entraînement. Réduit la covariance interne. Compatible avec Adam.

3

ModelCheckpoint (val_loss)

Sauvegarde automatiquement les poids du meilleur epoch (sur validation). Même si le training continue, le meilleur modèle est préservé.

Extraction de texte : Google Vision API

Transformer une image de panneau en données géolocalisables

☁️ Fonctionnement de l'OCR

1

Envoi de l'image à Google Cloud

La fonction detect_text(path) encode l'image en base64 et appelle l'API Vision. Les 1000 premières requêtes par mois sont gratuites.

2

Retour : texte + langue

L'API retourne : le texte complet de l'image, une liste de phrases individuelles, et un code locale (ex: "fr", "ja") représentant la langue détectée.

3

Locale = indice géographique fort

La langue détectée par Google Vision est la source de vérité. Elle servira à filtrer les résultats de géocodage pour ne garder que les pays où cette langue est parlée.

⚠️ Prérequis : renseigner le chemin vers le fichier JSON de credentials Google Cloud dans image_with_text_to_country_new.py ligne 13 avant tout lancement.

💻 Code de la fonction OCR

import os
from google.cloud import vision

# Credentials Google Cloud
os.environ["GOOGLE_APPLICATION_CREDENTIALS"] \
    = "/chemin/vers/credentials.json"

def detect_text(path):
    client = vision.ImageAnnotatorClient()
    with open(path, 'rb') as f:
        content = f.read()
    image = vision.Image(content=content)
    response = client.text_detection(image=image)
    texts = response.text_annotations

    full_text = texts[0].description  # tout le texte
    phrases = [t.description for t in texts[1:]]
    locale = texts[0].locale  # code langue
    return full_text, phrases, locale

Géocodage avec Nominatim

Convertir du texte brut en coordonnées GPS via OpenStreetMap

🗺️ Qu'est-ce que Nominatim ?

Nominatim est le moteur de géocodage officiel d'OpenStreetMap. Il traduit un texte quelconque (adresse, nom de lieu, rue…) en coordonnées GPS. Entièrement gratuit, sans clé API. 

from geopy.geocoders import Nominatim

geocoder = Nominatim(user_agent="geoguesser")

def text_to_location(text):
    location = geocoder.geocode(text)
    return location  # lat, lon, address

# Exemple
loc = text_to_location("Rue de Rivoli, Paris")
# → lat=48.86, lon=2.34
# → "Rue de Rivoli, Paris, France"

Filtre longueur min : les phrases de moins de 6 caractères sont écartées avant géocodage. Les mots courts comme "STOP" ou "EXIT" mèneraient à des faux positifs partout dans le monde.

🔍 Stratégie de filtrage

🔡 Phrases extraites par Vision API

Ex: ["Rue des Lilas", "PHARMACIE", "10", "Lyon", "Ouvert"]

↓
📏 Filtre ≥ 6 caractères

Élimine: "10", "STOP", "OK" → garde: "Rue des Lilas", "PHARMACIE", "Ouvert"

↓
📍 Géocodage de chaque phrase

Nominatim cherche chaque phrase → renvoie l'adresse complète avec pays

↓
🌍 Extraction du pays de l'adresse

Dernier segment après la dernière virgule de l'adresse retournée = pays candidat

Validation par langue : spaCy

Croiser la langue détectée par Vision avec la langue du pays géocodé

🔬 Rôle de spaCy dans le pipeline

spaCy avec le plugin spacy_langdetect peut détecter automatiquement la langue d'un texte. Ici, il analyse le dernier composant de l'adresse géocodée (le pays en texte libre) pour déterminer dans quelle langue ce composant est écrit. 

import spacy
from spacy_langdetect import LanguageDetector
from spacy.language import Language

@Language.factory("language_detector")
def get_lang_detector(nlp, name):
    return LanguageDetector()

nlp = spacy.load("en_core_web_sm")
nlp.add_pipe("language_detector", last=True)

def get_language_from_text(text):
    doc = nlp(text)
    return doc._.language["language"]

# "France" → "fr"  |  "Deutschland" → "de"
Prérequis : python -m spacy download en_core_web_sm

Bilan & Perspectives

Points forts du projet, limites connues et pistes d'amélioration

✅ Points forts

  • Approche multi-modale : paysage + drapeau + texte se complètent mutuellement
  • Pipeline entièrement automatisé de la collecte de données à l'inférence live
  • Utilisation de poids de classe + dropout pour gérer le déséquilibre et l'overfitting
  • Intégration de 3 APIs / services externes (Vision, Nominatim, Chrome)
  • Architecture CNN simple et efficace — deux blocs conv + trois couches denses

⚠️ Limites connues

  • Résolution codée en dur : 2560×1440 uniquement
  • Chemins Windows (\\) — non portable Linux/macOS
  • Bug dans la fonction test() du classifieur de continent
  • Aucun requirements.txt — dépendances implicites

🚀 Pistes d'amélioration

📐 Transfer Learning

Remplacer le CNN custom par ResNet50 / EfficientNet pré-entraîné sur ImageNet. Meilleure précision avec moins de données.

🖥️ Interface graphique

Ajouter une GUI (tkinter ou Electron) pour afficher les scores CNN et la carte directement sans terminal.

🔁 Data Augmentation

Rotations, flips, zoom, jitter de couleur — augmenter artificiellement le jeu d'entraînement pour améliorer la généralisation.

🌐 Portabilité

Remplacer les chemins Windows par pathlib.Path, ajouter un requirements.txt et automatiser la création de live_images/.
